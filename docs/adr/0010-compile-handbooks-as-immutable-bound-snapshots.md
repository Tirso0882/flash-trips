# Compile handbooks as immutable, bound snapshots

A Plan Revision is eligible for a Trip Handbook only while it is the current committed revision, every Approval required for its exact reviewed facts remains valid—including Travel Plan Approval—its applicable Evidence and required provider deep links remain valid, and `Revalidation Required` is false. The final qualifying Approval starts idempotent compilation outside the Approval transaction. Compilation failure does not revoke Approval, and retries retain the original bound inputs.

The Handbook Compiler produces one schema-versioned, format-neutral Handbook Document from canonical records without live lookups. A Handbook Snapshot becomes available atomically only after that document validates and deterministic renderers have produced semantically equivalent UTF-8 HTML, Markdown, and public JSON Handbook Exports. HTML is the primary readable and printable export, Markdown is the portable plain-text alternative, and JSON is a versioned, privacy-safe public contract rather than the internal document or database representation. Partial documents and exports remain inaccessible Run artefacts.

Each snapshot has an opaque identifier and a deterministic fingerprint binding the Plan Revision, exact qualifying Approvals, Evidence snapshot, policy set, canonical and public schemas, compiler and renderer-bundle versions, Handbook Document, and export checksums. Operational timestamps and execution identifiers do not vary that fingerprint, so identical retries deduplicate. PostgreSQL retains the immutable manifest, canonical document, exact export bytes, and checksums; reproducing an earlier delivery never depends on rerunning newer code.

Snapshots are never rewritten or selected by ambiguous “latest handbook” semantics. A renderer-only regeneration is explicit, may proceed without another Travel Plan Approval only when the Handbook Document fingerprint is unchanged and eligibility still holds, and creates a snapshot that explicitly supersedes its predecessor. Normal delivery uses the one eligible unsuperseded snapshot; an eligible predecessor requires explicit historical access. Semantic compiler, schema, or policy changes require deterministic revalidation and any resulting Approvals. A newly approved Plan Revision receives a new snapshot, while amendment, invalid Evidence, an invalid required Selection deep link, or policy invalidation derives `Revalidation Required` and blocks new viewing, download, regeneration, and re-export of affected snapshots. Existing downloads cannot be recalled.

The Handbook Document uses a closed typed structure for snapshot metadata, Trip Structure, approved Selections, chronological schedule, Budget Assessment, Travel Readiness, warnings and limitations, provider links, and an Evidence attribution index. Optional content is absent only through a typed reason. Dates, local times, IANA time zones, exact decimal amounts, ISO currency codes, unknown values, price ranges, and unpriced costs retain their canonical meaning across formats; renderers cannot estimate, omit, add, or reinterpret travel claims. Stable semantic-element identifiers, coverage reports, schema validation, and shared offline conformance fixtures fail compilation on missing, duplicated, or unsupported required content.

Every externally verifiable claim carries applicable Evidence attribution and observed time. Selected bookable items require validated policy-approved HTTPS provider deep links; informational claims carry source URLs. Rendering freezes validated labels and URLs, excludes credentials and unstable session parameters, and performs no live lookup. Affiliate or tracking parameters require explicit policy and visible disclosure. Evidence policy governs ordinary citation availability, while invalid required Selection links prevent new delivery.

Only the owning Planner with active Planner Access Status may retrieve a server-held Handbook Export. Each request uses an authenticated application endpoint and rechecks ownership, access, snapshot eligibility, and `Revalidation Required`; Flash Trips exposes no public object URL or durable bearer link. Operator authority grants no Trip access, and the initial product creates neither Companion access nor public sharing. A Handbook Delivery records the snapshot, format, Planner, authorisation result, timestamp, and checksum served without becoming an Approval or proof of opening.

Exports are self-contained offline artefacts except for visibly external provider and source links. They minimise private data, exclude External Identity values, email by default, access state, internal Approval machinery, execution traces, private Evidence payloads, and Operator information, and never become authoritative imports or Plan Amendments. HTML contains semantic, keyboard-accessible, print-friendly escaped content with no executable scripts or remote required assets. Markdown uses a documented CommonMark-compatible subset with raw HTML disabled. Modified downloads carry no claim of authenticity; the initial release uses persisted cryptographic checksums and authenticated comparison rather than digital signatures.

Canonical and public JSON schemas evolve independently under explicit compatibility rules. Breaking semantic changes require new major versions, and each renderer declares the exact canonical schema versions it supports. Unsupported combinations fail closed. Stored snapshots need no migration because their original bytes remain authoritative delivery records. Snapshot retention follows the owning Trip’s later privacy and retention policy; suspension or closure blocks access but does not itself delete records.
