# Architecture decision index

Read this index first. Open only the ADRs relevant to the task. Do not read the whole directory unless the task explicitly requires a review across all architecture decisions.

- [ADR 0001: Build Flash Trips as a greenfield product](0001-build-flash-trips-as-a-greenfield-product.md): Reuse verified domain knowledge from Wanderlisted, but not its architecture or compatibility contracts. Read when considering migration, reuse, or parity with Wanderlisted.
- [ADR 0002: Separate model proposals from deterministic authority](0002-separate-model-proposals-from-deterministic-authority.md): Models propose bounded typed selections while deterministic code controls facts, safety, money, permissions, and state. Read when assigning authority to AI or application code.
- [ADR 0003: Revise plans through validated amendments](0003-revise-plans-through-validated-amendments.md): Apply confirmed typed amendments as immutable Plan Revisions with validation and provenance. Read when changing plans, handling concurrency, invalidation, retries, or revision history.
- [ADR 0004: Adapt Wanderlisted evaluations without inheriting baselines](0004-adapt-wanderlisted-evaluations-without-inheriting-baselines.md): Reuse evaluation ideas and cases, but establish Flash Trips runners, evidence, and baselines. Read when importing evaluations or approving live capture and model judging.
- [ADR 0005: Use a capability-oriented modular monolith](0005-use-a-capability-oriented-modular-monolith.md): Start with a modular monolith whose deep capability modules own canonical records and keep LangGraph private. Read when choosing module boundaries, ports, adapters, deployment units, or orchestration ownership.
- [ADR 0006: Compile workflows from capability contracts](0006-compile-workflows-from-capability-contracts.md): Deterministically compile execution DAGs from typed capability contracts and validated state. Read when adding capabilities, dependencies, workflow gates, invalidation, reuse, or bounded repair.
- [ADR 0007: Use Azure for the initial hosted deployment](0007-use-azure-for-the-initial-hosted-deployment.md): Use the selected Azure services with deployment-neutral CI and immutable image promotion. Read when changing hosting, infrastructure, deployment, secrets, databases, or telemetry.
- [ADR 0008: Use External ID behind application-owned access](0008-use-external-id-behind-application-owned-access.md): Use Entra External ID for authentication while Flash Trips owns access, identity links, roles, ownership, and approvals. Read when working on sign-in, invitations, sessions, account linking, suspension, or identity-provider fallback.
- [ADR 0009: Route conversations through typed, scope-bound interactions](0009-route-conversations-through-typed-scope-bound-interactions.md): Treat chat as a typed transport bound to an explicit Conversation Scope, never as autonomous authority. Read when adding intents, chat commands, intake, approvals, clarifications, or Trip selection.
- [ADR 0010: Compile handbooks as immutable, bound snapshots](0010-compile-handbooks-as-immutable-bound-snapshots.md): Compile and deliver immutable Trip Handbook snapshots only from an eligible revision with valid approvals and Evidence. Read when changing handbook generation, delivery, retries, supersession, or revalidation.
- [ADR 0011: Use a conditional, role-bound provider portfolio](0011-use-a-conditional-role-bound-provider-portfolio.md): Activate providers only for qualified roles and markets under versioned profiles and explicit fallbacks. Read when selecting providers, markets, deep links, advisory sources, fallback behavior, licensing, or cost.
- [ADR 0012: Expose typed commands, queries, and durable Run observation](0012-expose-typed-commands-queries-and-durable-run-observation.md): Expose versioned typed HTTP use cases, idempotent commands, authoritative queries, and durable per-Run observation. Read when changing APIs, BFF boundaries, command acceptance, SSE, idempotency, or execution recovery.
- [ADR 0013: Make Turn and Run inspection a durable contract](0013-make-turn-and-run-inspection-a-durable-contract.md): Persist append-only typed inspection records that reconstruct Turns, Runs, decisions, attempts, costs, and terminal outcomes. Read when adding observability, timelines, replay, causality, inspection storage, or explanations.
- [ADR 0014: Protect private Trips with fail-closed security boundaries](0014-protect-private-trips-with-fail-closed-security-boundaries.md): Keep private Trip data behind application-owned, fail-closed identity, session, ownership, privacy, audit, and incident controls. Read when handling authentication, authorization, personal data, external calls, abuse, secrets, deletion, or security incidents.
- [ADR 0015: Evaluate releases with layered, risk-weighted evidence](0015-evaluate-releases-with-layered-risk-weighted-evidence.md): Gate releases with deterministic checks, semantic judging, pairwise comparison, and calibrated human evidence. Read when defining quality gates, cases, baselines, scoring, judges, or promotion criteria.
- [ADR 0016: Use normalized PostgreSQL with explicit retention](0016-use-normalized-postgresql-with-explicit-retention.md): Use one normalized PostgreSQL source of truth with explicit transactions, migrations, storage classes, retention, and deletion. Read when changing persistence, schemas, constraints, migrations, backup, retention, or data removal.
- [ADR 0017: Structure the repository with enforced module and quality gates](0017-structure-the-repository-with-enforced-module-and-quality-gates.md): Keep one repository with a Python modular monolith, Next.js app, generated contracts, evaluations, and enforced import and quality boundaries. Read when changing repository layout, packages, module imports, generated artifacts, or CI gates.
- [ADR 0018: Route reasoning deterministically and reserve external cost](0018-route-reasoning-deterministically-and-reserve-external-cost.md): Choose reasoning through versioned policy and reserve worst-case external cost before dispatch. Read when adding models, reasoning profiles, quotas, retries, paid providers, caching, budgets, or cost lineage.
- [ADR 0019: Stage security controls by pilot cohort](0019-stage-security-controls-by-pilot-cohort.md): Phase only deferrable security administration across pilot cohorts while preserving identity, ownership, session, and token boundaries from the start. Read when planning pilot scope, sequencing security work, or expanding access.
